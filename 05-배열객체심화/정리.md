1. reduce - 왜 필요한가?
   지금까지 배운 걸로는 합께를 낼 수가 없습니다.

const nums = [10,20,30]
nums.map(...) //배열이 나옴.
nums.filter(...) //배열이 나옴.

60을 만들어내는 방법이 없습니다. 원래 배열에 60이란 건 없으니까요. reduce는 배열을 없던 값하나로 접는 메서드 입니다.

map : [a,b,c] -> [x,y,z] 개수 그대로
filter : [a,b,c] -> [a,c] 개수 줄어듦
reduce : [a,b,c] -> 값 하나 <- 이것만 다름

문법

arr.reduce((acc, cur) => 다음\_acc, 초깃값)
↑ ↑
누적값 현재값

acc는 accumulator(누적값), cur은 current(현재값) 의 관례적 이름입니다.

핵심 규칙 하나: 화살표가 반환한 값이 다음 회차의 acc가 됩니다.
실제로 도는 걸 찍어봤습니다.

const nums = [10,20,30]
nums.reduce((acc,cur)=>{
console.log(`누적값=${acc}, 현재값=${cur} -> 반환{acc + cur}`)
return acc + cur
},0);

누적값=0, 현재값=10 → 반환 10
누적값=10, 현재값=20 → 반환 30
누적값=30, 현재값=30 → 반환 60
최종 결과: 60

★ forEach가 console.log를 세 번 실행하고 끝나는 거라면, reduce는 세 번 실행하면서 값을 다음으로 넘긴다는 게 차이입니다.

실전 형태

중괄호와 return을 뺴면 실무에서 보는 모양이 됩니다.

nums.reduce((acc,cur)=>acc+cur,0) //60
객체 배열이면 cur이 객체 입니다.
누적값은 아무 타입이나 됩니다.

여기가 reduce 의 진짜 힘입니다. acc가 꼭 숫자일 필요가 없어요.

const books = [
  { title: "자바스크립트", pages: 300 },
  { title: "PHP", pages: 450 },
  { title: "CSS", pages: 200 }
]

1-1 숫자 - 합계
books.reduce((acc,cur)=>acc+cur,0) // 950

1-2 객체 - 최댓값 찾기
books.reduce((acc,cur)=>cur.pages > acc.pages ? cur : acc)

1. reduce - 왜 필요한가?
   지금까지 배운 걸로는 합께를 낼 수가 없습니다.

const nums = [10,20,30]
nums.map(...) //배열이 나옴.
nums.filter(...) //배열이 나옴.

60을 만들어내는 방법이 없습니다. 원래 배열에 60이란 건 없으니까요. reduce는 배열을 없던 값하나로 접는 메서드 입니다.

map : [a,b,c] -> [x,y,z] 개수 그대로
filter : [a,b,c] -> [a,c] 개수 줄어듦
reduce : [a,b,c] -> 값 하나 <- 이것만 다름

문법

arr.reduce((acc, cur) => 반환값, 초깃값)
             ↑    ↑
           누적값 현재값

acc는 accumulator(누적값), cur은 current(현재값) 의 관례적 이름입니다.

핵심 규칙 하나: 화살표가 반환한 값이 다음 회차의 acc가 됩니다.
실제로 도는 걸 찍어봤습니다.

const nums = [10,20,30]
nums.reduce((acc,cur)=>{
console.log(`누적값=${acc}, 현재값=${cur} -> 반환{acc + cur}`)
return acc + cur
},0);

누적값=0, 현재값=10 → 반환 10
누적값=10, 현재값=20 → 반환 30
누적값=30, 현재값=30 → 반환 60
최종 결과: 60

★ forEach가 console.log를 세 번 실행하고 끝나는 거라면, reduce는 세 번 실행하면서 값을 다음으로 넘긴다는 게 차이입니다.

실전 형태

중괄호와 return을 뺴면 실무에서 보는 모양이 됩니다.

nums.reduce((acc,cur)=>acc+cur,0) //60
객체 배열이면 cur이 객체 입니다.
누적값은 아무 타입이나 됩니다.

여기가 reduce 의 진짜 힘입니다. acc가 꼭 숫자일 필요가 없어요.

const books = [
  { title: "자바스크립트", pages: 300 },
  { title: "PHP", pages: 450 },
  { title: "CSS", pages: 200 }
]

숫자 — 합계
books.reduce((acc, cur) => acc + cur.pages, 0)      // 950

객체 — 최댓값 찾기
books.reduce((acc, cur) => cur.pages > acc.pages ? cur : acc)
// { title: 'PHP', pages: 450 }
"지금까지 제일 두꺼운 책"을 계속 들고 가는 겁니다. acc가 책 객체예요.

문자열 — 이어붙이기
books.reduce((acc, cur) => acc + cur.title + " / ", "")
// "자바스크립트 / PHP / CSS / "

배열 — map도 흉내낼 수 있음
books.reduce((acc, cur) => [...acc, cur.title], [])
// [ '자바스크립트', 'PHP', 'CSS' ]

map으로 하면 될 걸 굳이 이렇게 쓰진 않습니다. 다만 reduce가 map·filter를 다 포함할 만큼 범용이라는 걸 보여주는 예입니다.
초깃값이 곧 acc의 타입을 정합니다. 숫자 만들 거면 0, 문자열이면 "", 배열이면 [], 객체면 {}.

초깃값을 생략하면

[10, 20, 30].reduce((acc, cur) => acc + cur)   // 60 — 잘 됨

첫 요소가 초깃값이 되고 둘째부터 돕니다. 숫자 배열이면 문제없어요.

근데 객체 배열에서 빼면:

books.reduce((acc, cur) => acc + cur.pages)
// "[object Object]450200"    ← 문자열이 나옴


첫 acc가 책 객체라서 객체 + 450이 문자열 연결이 돼버립니다.

그리고 빈 배열이면 아예 터집니다:

[].reduce((acc, cur) => acc + cur)
→ TypeError: Reduce of empty array with no initial value

[].reduce((acc, cur) => acc + cur, 0)
→ 0

규칙: 초깃값은 항상 쓰세요. 최댓값 찾기 처럼 "요소 중 하나를 고르는" 경우만 예외입니다.

PHP와 비교하면

array_sum($prices)                              // 합계만
array_reduce($books, fn($acc, $b) => ..., 0)    // 범용

PHP는 array_sum이 따로 있는데 JS엔 없습니다. reduce가 그 자리를 다 씁니다.

2. part2 -  some / every

const nums = [10,20,30]

nums.some(n=>n > 25)  //true  - 30이 있으니까 (하나라도)
nums.every(n=>n > 25) //false - 10, 20이 안 맞음 (전부)
nums.every(n=>n > 5)  //true  - 전부 맞음.

some은 찾는 즉시 멈춥니다:

nums.some(n => { console.log("검사중:", n); return n > 15 })
검사중: 10
검사중: 20      ← 여기서 true, 30은 검사 안 함

find와 뭐가 다른가 ? 

const users = [
  { name: "노벨", age: 21 },
  { name: "지민", age: 17 }
]

users.find(u => u.age >= 20)   // { name: '노벨', age: 21 }   ← 객체
users.some(u => u.age >= 20)   // true                        ← 불리언

users.find(u => u.age >= 99)   // undefined
users.some(u => u.age >= 99)   // false

┌──────┬──────────────────────┬────────────────────────────┐
│      │       묻는 것        │        돌려주는 것         │
├──────┼──────────────────────┼────────────────────────────┤
│ find │ 누구가 조건에 맞나?  │ 그 요소 (없으면 undefined) │
├──────┼──────────────────────┼────────────────────────────┤\
│ some │ 조건에 맞는 게 있나? │ true / false               │
└──────┴──────────────────────┴────────────────────────────┘

!주의 저번에 Q7에서 filter(e => e.items.find(...))를 쓰셨는데, filter는 true/false를 원합니다. find가 돌려준 객체가 truthy라서 우연히 동작했어요. some은 애초에 true/false를 내놓으니 정확합니다.

함정 하나
[].every(n=>n>100) //true <- 빈 배열은 항상 true
[].some(n=>n>100) //false

"모든 요소가 맞다"는 게 요소가 없으면 자동으로 참이 됩니다. every 쓸 땐 배열이 빌 수 있는지 확인하세요. 

PHP 대응

PHP 8.4부터 array_any/array_all이 생겼는데, 그전엔 이렇게 썻습니다:
count(array_filter($arr,$fn)) > 0 //some
count(array_filter($arr,$fn)) === count($arr) //every

JS는 전용 메서드가 있고, 중간에 멈추기까지 합니다.

3. PART 3 — ?? (널 병합)

A ?? B    // A가 null 이거나 undefined면 B, 아니면 A

?.이 "없을 수도 있는 걸 안전하게 꺼내기"였다면, ??는 "없으면 이걸로 대신" 입니다. 짝으로 씁니다.

||와 뭐가 다른가

||도 비슷해 보이는데, 걸러내는 범위가 다릅니다.

값         ??→          ||→
─────────────────────────────────
undefined  기본값        기본값
null       기본값        기본값
0          0            기본값     ← 다름
""         ""           기본값     ← 다름
false      false        기본값     ← 다름
NaN        NaN          기본값     ← 다름

- || — falsy면 전부 넘어감 (0, "", false, NaN 포함)
- ?? — null/undefined만 넘어감

이게 왜 버그가 되는지

const users = [
  { name: "노벨", point: 0, nick: "" },
  { name: "지민" },                        // point 없음
  { name: "수아", point: 500, nick: "수아님" }
]

포인트 표시, 없으면 "미가입":
users.map(u => u.point ?? "미가입")   // [ 0, '미가입', 500 ]        ✅
users.map(u => u.point || "미가입")   // [ '미가입', '미가입', 500 ]  ❌

노벨은 포인트가 0점인 가입자입니다. ||는 0을 "없음"으로 처리해서 미가입으로 만들어버렸어요. 실제 서비스면 CS 들어옵니다.

닉네임, 없으면 본명:
users.map(u => u.nick ?? u.name)   // [ '', '지민', '수아님' ]
users.map(u => u.nick || u.name)   // [ '노벨', '지민', '수아님' ]

여기선 ||가 맞습니다. 빈 문자열 닉네임은 "없는 것"으로 쳐야 하니까요.

정답은 상황마다 다릅니다. 다만 기준은:

▎ 숫자를 다루면 ??. 0이 정상 값일 수 있으니까요.
▎ 문자열에서 빈칸을 "없음"으로 볼 거면 ||.

?.과 붙여 쓰기

orders.map(o => o.customer?.grade ?? "일반")
// [ 'VIP', '일반', '일반' ]

한 줄로 두 단계를 막습니다:
- ?. — customer가 없으면 undefined (에러 안 남)
- ?? — 그 undefined를 "일반"으로

복습-2 Q4가 이 한 줄입니다. 원래 쓰신 건:
e.customer?.grade === undefined ? "일반" : e.customer?.grade

PHP 대응

$grade = $user['grade'] ?? "일반";
PHP에도 똑같은 ??가 있습니다 (PHP 7.0부터). 동작도 같아요, PHP는 "NULL이거나 없는 키"를 넘깁니다.

4. PART4 - 객체 단축 속성

변수명과 키 이름이 같으면 한 번만 씁니다. 
const name = "노벨",age = 21 
{name: name, age: age} //길게
{name,age} //단축 - 결과 같음

둘다 {name: "노벨"age: 21}입니다.

섞어 써도 됩니다.
{name,age,city:"서울"}  // { name: '노벨', age: 21, city: '서울' }

구조 분해와 정확히 반대

const {name} = user //꺼낼 때 - 객체에서 변수로
const obj = {name} //넣을때 변수에서 객체로

같은 문법이 좌변에 있으면 꺼내기, 우변에 있으면 넣기입니다.
계산된 키 [ ]

reduce로 객체 만들때 필요한 문법입니다.
const key = "grade"
{[key]:"VIP",["is"+"New"]:true}
//{grade:"VIP",IsNew: true}
{ key: "VIP" } 라고 쓰면 키가 문자 그대로 "key"가 됩니다. 대괄호로 감싸야 변수의 값이 키가 돼요.

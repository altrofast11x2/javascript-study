# 06 - DOM
1. DOM은 왜 필요한가

지금까지 만든 건 전부 콘솔 안에서만 살아있었습니다.

scores.forEach(s => console.log(`${s}점`))   // F12 눌러야 보임

사용자는 F12를 안 누릅니다. 반대로 HTML만으로는 값이 안 바뀌어요.

<h1>95점</h1>   <!-- 점수가 바뀌면? 파일을 손으로 고쳐야 함 -->

HTML은 죽은 글자입니다. 그 죽은 글자를 JS가 만질 수 있게 바꿔놓은 게 DOM이고, Day 06의 전부는 "JS로 계산한 값을 화면에 꽂아넣기" 입니다.

2. DOM은 HTML 파일이 아니라 복사본입니다 ⭐

index.html 파일          브라우저 메모리
─────────────            ─────────────
<h1>DOM 연습</h1>   →    { textContent: "DOM 연습", classList: ..., ... }
   설계도                     실제 건물

브라우저가 설계도를 읽어서 건물을 짓습니다. JS가 만지는 건 지어진 건물이지 설계도가 아니에요.

$("#title").textContent = "DOM 정복"

화면은 바뀌지만 index.html 파일은 그대로입니다. 그래서 새로고침하면 원래대로 돌아가요. 버그가 아니라 정상입니다.

▎ 나중에 "고친 게 왜 저장이 안 되지?" 할 때 이 문단을 떠올리세요. 영구 저장은 Day 08·09의 일입니다.

3. lib.js 1번 줄 해부 — $

const $ = e => document.querySelector(e)

Day 03에서 배운 화살표 함수 축약형입니다. e(선택자)를 받아서 document.querySelector(e)를 return 해요. 몸통이 한 줄이라 {}와 return이 생략된 겁니다.

querySelector가 이긴 이유 — CSS 선택자를 그대로 씁니다

옛날 방식이 셋 있었습니다. 남의 코드에서 만나면 알아봐야 하니 보고만 가세요.

document.getElementById("title")          // # 없이 씁니다
document.getElementsByClassName("desc")
document.getElementsByTagName("p")

이름도 길고 #/. 규칙도 제각각입니다. querySelector는 CSS에서 쓰던 걸 그대로 씁니다.

$("h1")             // 태그
$("#title")         // 아이디 — # 붙임

querySelector가 이긴 이유 — CSS 선택자를 그대로 씁니다

옛날 방식이 셋 있었습니다. 남의 코드에서 만나면 알아봐야 하니 보고만 가세요.

document.getElementById("title")          // # 없이 씁니다
document.getElementsByClassName("desc")
document.getElementsByTagName("p")

이름도 길고 #/. 규칙도 제각각입니다. querySelector는 CSS에서 쓰던 걸 그대로 씁니다.

$("h1")             // 태그
$("#title")         // 아이디 — # 붙임
$(".desc")          // 클래스 — . 붙임
$("body > p")       // 자식
$("p.desc")         // p 이면서 .desc
$("[data-name]")    // 속성이 있는 것
$("p:last-child")   // 가상 선택자

CSS에서 되는 건 전부 됩니다. 새 문법을 안 외워도 돼요.

$는 하나만 줍니다 ⭐

노벨 님 파일에 .desc가 3개인데:

$(".desc")     // <p>첫 번째 문단</p>  ← 하나만!
$$(".desc")    // 3개 전부

$냐 $$냐 하나 차이입니다. 이거 놓쳐서 "왜 하나만 바뀌지?" 하는 경우가 아주 많아요.

못 찾으면 null입니다

$("#없는거")              // null   ← undefined 아님!
$("#없는거").textContent   // ❌ TypeError: Cannot read properties of null
$("#없는거")?.textContent  // undefined  ← Day 04의 ?.

오타 하나로 null이 되고 다음 줄에서 터집니다. DOM 에러 1위예요.

4. lib.js 2번 줄 해부 — $$ ⭐⭐

const $$ = e => [...document.querySelectorAll(e)]
//              ^^^^                          ^

저 대괄호가 오늘의 핵심입니다. 왜 붙였을까요?

querySelectorAll이 주는 건 NodeList인데, 배열처럼 생겼지만 배열이 아닙니다.

const ps = document.querySelectorAll(".desc")

ps.length        // 3    ✅
ps[0]            // 첫 번째 <p>  ✅
ps.forEach(...)  // ✅  forEach 하나만 예외적으로 있음
ps.map(...)      // ❌ TypeError: ps.map is not a function
ps.filter(...)   // ❌

Day 05에서 보신 prices.map is not a function과 완전히 같은 상황입니다. 객체에 map이 없었던 것처럼, NodeList에도 없어요.

[...ps].map(p => p.textContent)   // ✅ 스프레드로 진짜 배열을 만들면 됨

lib.js의 대괄호가 바로 이겁니다. $$는 항상 진짜 배열을 줘요. 그래서 map/filter/reduce를 바로 붙일 수 있습니다.

$$(".desc").map(p => p.textContent)      // ✅ 바로 됨
$$(".desc").filter(p => ...)             // ✅
document.querySelectorAll(".desc").map() // ❌ 터짐

노벨 님이 이미 해결책을 갖고 시작하신 겁니다. 대괄호 하나가 그 일을 하고 있었어요.

조용히 실패하는 함정 ⭐⭐

$$(".desc").textContent = "야호"    // ❌ 에러도 안 나고, 아무 일도 안 일어남

$$는 배열을 줍니다. 배열에 textContent를 넣으면 JS는 그냥 배열에 이상한 속성을 하나 만들고 끝나요. 에러가 안 나서 제일 찾기 어렵습니다.

$$(".desc")[0].textContent = "야호"              // ✅ 하나 꺼내서
$$(".desc").forEach(p => p.textContent = "야호") // ✅ 전부면 돌려야 함

"여러 개를 잡았으면 반드시 돌려야 한다." 이게 규칙입니다.

5. $의 한계 — 안에서 찾기

$는 항상 document 전체에서 찾습니다. 특정 요소 안에서만 찾고 싶으면 요소에 직접 붙여야 해요.

const box = $("#box")

$(".desc")                    // 문서 전체에서 첫 번째
box.querySelector(".desc")    // box 안에서만 첫 번째
box.querySelectorAll(".desc") // box 안에서 전부

lib.js의 $로는 이게 안 됩니다. 지금은 몰라도 되지만, 나중에 카드 여러 개를 다룰 때 필요해져요. 그때 lib.js를 이렇게 고치면 됩니다.

const $ = (e, p = document) => p.querySelector(e)
//             ^^^^^^^^^^^^ Day 03의 기본값 매개변수
$(".desc")        // 전체에서
$(".desc", box)   // box 안에서

▎ 지금 당장 고치지는 마세요. "필요해지면 이렇게 확장할 수 있다" 는 것만 알아두시면 됩니다.

6. 실행 시점 — <script>를 왜 아래에 두나 ⭐⭐

노벨 님은 이미 맞게 하셨는데, 이유를 알고 가셔야 합니다.

<head>
  <script src="../lib.js"></script>
  <script>
    console.log($("#title"))   // null  ← ???
  </script>
</head>
<body>
  <h1 id="title">DOM 연습</h1>
</body>

브라우저는 위에서 아래로 한 줄씩 읽습니다. <head>의 스크립트가 실행되는 순간 <h1>은 아직 존재하지 않아요.

읽는 중...   <head>의 script 실행  ← 이 시점엔 body가 텅 빔
계속 읽음... <h1> 생성

lib.js도 마찬가지입니다. lib.js를 먼저 부르고 그 아래서 $를 써야 해요. 순서가 바뀌면 $ is not defined가 납니다. 지금 파일은 맞게 돼 있습니다.

  <script src="../lib.js"></script>   ← 먼저
  <script>  $("#title")  </script>    ← 나중
</body>

▎ <head>에 두고 싶으면 <script defer src="...">를 씁니다. 완전한 해결은 Day 07의 DOMContentLoaded예요.

7. 글자 읽고 쓰기 ⭐⭐

const h = $("#title")

console.log(h.textContent)   // "DOM 연습"   ← 읽기
h.textContent = "DOM 정복"    //             ← 쓰기

같은 속성이 읽기도 쓰기도 됩니다. 그냥 객체 속성이니까요.

┌─────────────┬───────────────┬────────────────────┐
│             │ 태그를 만나면 │    숨겨진 글자     │
├─────────────┼───────────────┼────────────────────┤
│ textContent │ 글자로 취급   │ 보임               │
├─────────────┼───────────────┼────────────────────┤
│ innerHTML   │ HTML로 해석   │ —                  │
├─────────────┼───────────────┼────────────────────┤
│ innerText   │ 글자로 취급   │ 안 보임 (CSS 반영) │
└─────────────┴───────────────┴────────────────────┘

h.textContent = "<b>굵게</b>"   // 화면:  <b>굵게</b>   ← 글자 그대로
h.innerHTML   = "<b>굵게</b>"   // 화면:  굵게          ← 진짜 굵어짐

기본은 textContent입니다. 이유가 둘이에요.

1. 안전합니다. 사용자 입력을 innerHTML에 넣으면 거기 섞인 <script>까지 실행됩니다.
2. 빠릅니다. innerHTML은 문자열을 파싱해 태그를 새로 만들고, textContent는 글자만 갈아끼웁니다.

8. 속성 — 프로퍼티와 getAttribute는 다릅니다 ⭐

표준 속성은 그냥 점으로 됩니다.

img.src = "cat.png"
input.value = "노벨"       // input의 입력값
input.disabled = true      // boolean — "true" 문자열 아님

getAttribute도 있는데 미묘하게 다릅니다.

<a id="link" href="/about">링크</a>
$("#link").href                   // "http://localhost/about"  ← 브라우저가 완성한 주소
$("#link").getAttribute("href")   // "/about"                  ← 파일에 적힌 글자 그대로

- 프로퍼티(.href) = 브라우저가 해석한 지금 값
- getAttribute = HTML에 적혀 있는 글자

input에서 제일 티가 납니다. 사용자가 타이핑하면 .value는 바뀌지만 getAttribute("value")는 처음 값 그대로예요.

data- 속성과 dataset

노벨 님 #box에 이미 있습니다.

$("#box").dataset.name     // "상자"
$("#box").dataset.price    // "5000"   ⚠️ 문자열! 숫자 아님

HTML 속성은 전부 문자열입니다. 예외 없어요.

$("#box").dataset.price + 1000            // "50001000"  ← 문자열 이어붙이기!
Number($("#box").dataset.price) + 1000    // 6000        ✅

Day 01의 1 == "1" 얘기가 여기서 실제로 터집니다.

▎ data-는 떼고 읽고, data-user-name이면 dataset.userName으로 카멜케이스가 됩니다.

9. 클래스 — classList ⭐⭐⭐

실무에서 제일 많이 씁니다. 노벨 님이 CSS에 .hi, .hide를 미리 만들어두신 게 정석이에요.

$("#box").classList.add("hi")        // 붙이기
$("#box").classList.remove("hi")     // 떼기
$("#box").classList.toggle("hi")     // 있으면 떼고 없으면 붙이고
$("#box").classList.contains("hi")   // true / false

toggle은 확인할 필요가 없습니다.

// ❌ 이렇게 안 해도 됨
if (box.classList.contains("hide")) box.classList.remove("hide")
else box.classList.add("hide")

// ✅ 한 줄
box.classList.toggle("hide")

▎ className이라는 옛날 방식은 쓰지 마세요. 문자열을 통째로 덮어써서 기존 클래스가 날아갑니다.
▎ box.className = "hi"        // ❌ 원래 있던 클래스 전부 사라짐
▎ box.classList.add("hi")     // ✅ 있던 건 두고 하나만 추가

10. 스타일 — style은 카멜케이스 ⚠️

box.style.backgroundColor = "skyblue"   // background-color ❌ → backgroundColor ✅
box.style.fontSize = "20px"             // 단위 꼭!

CSS의 하이픈이 JS에선 대문자가 됩니다. -는 빼기 연산자라 속성명에 못 쓰거든요.

단위를 빼먹으면 조용히 무시됩니다.

box.style.width = 200       // ❌ 아무 일도 안 일어남
box.style.width = "200px"   // ✅

style보다 classList를 쓰세요

모양은 CSS가, 동작은 JS가. 노벨 님은 이미 style.css에 리셋까지 만들어 쓰고 계시니 감이 있으실 겁니다. 색 하나 바꾸려고 JS 파일을 뒤지는 일이 없어져요.

11. 가족 찾기 — 부모·자식·형제

잡은 요소에서 옆으로 이동할 수 있습니다.

const p = $(".desc")

p.parentElement            // 부모
p.nextElementSibling       // 다음 형제 → 두 번째 .desc
p.previousElementSibling   // 이전 형제
p.closest("body")          // 위로 올라가며 조건에 맞는 첫 조상
p.children                 // 자식 전부 (HTMLCollection — 이것도 배열 아님!)

▎ parentNode / nextSibling 같은 Element 없는 버전도 있는데, 줄바꿈·공백까지 세서 원하는 게 안 나옵니다. 항상 Element가 붙은 걸 쓰세요.

closest는 Day 07(이벤트)에서 진가를 발휘합니다.

12. 최종 목적지 — $$ + 배열 메서드

Day 04·05를 왜 그렇게 오래 했는지가 여기서 드러납니다.

$$(".desc")
  .filter(p => p.textContent.includes("세"))
  .forEach(p => p.classList.add("hi"))

$$가 진짜 배열을 주니까 그동안 배운 게 전부 그대로 먹힙니다. map으로 글자 뽑고, filter로 고르고, forEach로 적용하고. 이게 DOM 조작의 실체예요.

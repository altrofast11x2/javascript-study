# 11 - 폼 검증
1. 왜 JS 검증이 필요한가

입력창을 만들었으면 반드시 따라오는 질문이 있습니다. "사용자가 아무거나 넣으면?"

이름 칸에 공백만, 나이 칸에 "열살", 이메일 칸에 "ㅋㅋㅋ", 비밀번호에 "1".
검증이 없는 폼은 그걸 전부 통과시킵니다. 그리고 서버로 보냅니다.

검증은 두 군데서 합니다.

┌───────────────┬──────────────────────────┬──────────────┐
│ 어디서        │ 목적                     │ 믿을 수 있나 │
├───────────────┼──────────────────────────┼──────────────┤
│ 브라우저 (JS) │ 사용자에게 빨리 알려주기 │ ✗ 못 믿는다  │
├───────────────┼──────────────────────────┼──────────────┤
│ 서버 (PHP 등) │ 데이터를 지키기          │ ○ 이게 진짜  │
└───────────────┴──────────────────────────┴──────────────┘

⭐ JS 검증은 **친절**이고, 서버 검증은 **보안**입니다.

JS 검증은 개발자도구로 1초면 무력화됩니다. novalidate 를 지우거나 함수를 덮어쓰면 끝이에요.
그래서 둘 다 합니다. 지금은 앞쪽을 배우고, 13-PHP연동 에서 뒤쪽을 봅니다.

2. 공짜로 주는 것 - HTML 기본 검증

JS 한 줄 없이도 브라우저가 해주는 게 꽤 많습니다.

<input required>
<input type="email">
<input type="number" min="1" max="120">
<input minlength="2" maxlength="10">
<input pattern="[0-9]{3}-[0-9]{4}">

┌─────────────┬──────────────────┬─────────────────────────┐
│ 속성        │ 하는 일          │ 주의                    │
├─────────────┼──────────────────┼─────────────────────────┤
│ required    │ 비어 있으면 막음 │ 체크박스/라디오에도 됨  │
├─────────────┼──────────────────┼─────────────────────────┤
│ type=email  │ @ 모양 검사      │ 브라우저가 판단해줌 ⭐  │
├─────────────┼──────────────────┼─────────────────────────┤
│ type=number │ 숫자만           │ 빈 값은 통과 ⭐         │
├─────────────┼──────────────────┼─────────────────────────┤
│ min / max   │ 숫자 범위        │ number, date 에만       │
├─────────────┼──────────────────┼─────────────────────────┤
│ minlength   │ 최소 글자 수     │ 타이핑은 안 막음        │
├─────────────┼──────────────────┼─────────────────────────┤
│ maxlength   │ 최대 글자 수     │ 아예 더 못 치게 막음    │
├─────────────┼──────────────────┼─────────────────────────┤
│ step        │ 증가 단위        │ step="0.1" 같은 것      │
├─────────────┼──────────────────┼─────────────────────────┤
│ pattern     │ 정규식           │ ^ $ 는 자동으로 붙음 ⭐ │
└─────────────┴──────────────────┴─────────────────────────┘

이것만으로도 submit 이 막히고 말풍선이 뜹니다. **먼저 이걸 쓰세요.**
JS 로 처음부터 다 만들 필요 없습니다.

⭐ 함정 1 : type="number" 는 빈 값을 허용합니다. 비어 있으면 min/max 검사를 아예 안 해요.
           비면 안 되는 칸이면 required 를 같이 붙여야 합니다.
⭐ 함정 2 : pattern 은 전체 일치입니다. ^ $ 를 안 써도 전체를 봅니다.
           (JS 정규식은 반대입니다. 10번 항목에서 봅니다)

3. 그럼 왜 직접 만드나

기본 말풍선에는 한계가 있습니다.

┌──────────────────────────────┬─────────────────────────────┐
│ 하고 싶은 것                 │ 기본 말풍선                 │
├──────────────────────────────┼─────────────────────────────┤
│ 글씨 / 색 바꾸기             │ 못 함                       │
├──────────────────────────────┼─────────────────────────────┤
│ 위치 바꾸기                  │ 못 함                       │
├──────────────────────────────┼─────────────────────────────┤
│ 에러 여러 개 한번에 보여주기 │ 첫 칸 하나만 뜸             │
├──────────────────────────────┼─────────────────────────────┤
│ 문구를 내가 정하기           │ setCustomValidity 로 일부만 │
├──────────────────────────────┼─────────────────────────────┤
│ 한국어로 고정                │ 브라우저 언어를 따라감      │
└──────────────────────────────┴─────────────────────────────┘

디자인 시안대로 만들어야 하면 기본 말풍선으로는 안 됩니다. 그래서 끕니다.

<form id="f" novalidate>

novalidate 를 붙이면 **말풍선이 안 뜨고 submit 이 자동으로 막히지 않습니다.**
검사 기능 자체는 그대로 살아 있습니다. checkValidity() 는 여전히 동작해요.
자동 차단과 말풍선만 꺼지는 겁니다. 운전대를 내가 잡는 거죠.

4. 브라우저가 이미 아는 것 - Validity

novalidate 를 켰어도 브라우저의 판단은 공짜로 쓸 수 있습니다.

input.checkValidity()      // true / false
input.validity            // 왜 틀렸는지가 들어있는 객체
input.validationMessage   // 브라우저의 기본 메시지 문자열

┌──────────────────┬────────────────────────────────┐
│ validity 의 속성 │ 언제 true                      │
├──────────────────┼────────────────────────────────┤
│ valueMissing     │ required 인데 비었다           │
├──────────────────┼────────────────────────────────┤
│ typeMismatch     │ type=email / url 모양이 아니다 │
├──────────────────┼────────────────────────────────┤
│ tooShort         │ minlength 보다 짧다            │
├──────────────────┼────────────────────────────────┤
│ tooLong          │ maxlength 보다 길다            │
├──────────────────┼────────────────────────────────┤
│ rangeUnderflow   │ min 보다 작다                  │
├──────────────────┼────────────────────────────────┤
│ rangeOverflow    │ max 보다 크다                  │
├──────────────────┼────────────────────────────────┤
│ patternMismatch  │ pattern 에 안 맞다             │
├──────────────────┼────────────────────────────────┤
│ stepMismatch     │ step 단위에 안 맞다            │
├──────────────────┼────────────────────────────────┤
│ valid            │ 다 통과했다                    │
└──────────────────┴────────────────────────────────┘

const el = $("#email")
el.value = "abc"
el.checkValidity()           // false
el.validity.typeMismatch     // true
el.validity.valueMissing     // false

이걸 쓰면 "이메일 형식인가" 를 내가 정규식으로 안 짜도 됩니다.

폼 전체도 됩니다.

form.checkValidity()     // 조용히 검사만. true / false
form.reportValidity()    // 검사 + 말풍선까지 띄움

⭐ reportValidity() 는 novalidate 여도 말풍선을 띄웁니다. 헷갈리는 지점입니다.
  novalidate 가 끄는 것은 "자동" 검사일 뿐, 내가 직접 부르는 것은 막지 않습니다.

내가 만든 에러도 브라우저에게 알려줄 수 있습니다.

el.setCustomValidity("이미 쓰는 아이디입니다")   // 이 칸을 "틀림" 으로 만든다
el.setCustomValidity("")                        // 해제

⭐⭐ 함정 : setCustomValidity 에 메시지가 남아 있으면 그 칸은 **영원히 invalid** 입니다.
    해제는 빈 문자열입니다. 안 지우면 사용자가 다 고쳐도 submit 이 안 됩니다.
    "분명히 맞게 썼는데 안 넘어가요" 의 범인이 거의 이겁니다.

5. submit 을 잡는다 (07 복습)

$("#f").addEventListener("submit", e => {
  e.preventDefault()
  // 여기서 검사
})

07 에서 한 것 그대로입니다. 두 가지만 다시 짚습니다.

· 이벤트는 button 의 click 이 아니라 **form 의 submit** 에 답니다.
  Enter 키로도 submit 되기 때문입니다. click 에 달면 Enter 를 놓칩니다.
· e.preventDefault() 를 안 하면 페이지가 새로고침됩니다.
  콘솔 로그도 같이 날아가서 "아무 일도 안 일어난 것처럼" 보입니다.

┌────────────────┬────────────────────────────────────────┐
│ button 의 type │ 하는 일                                │
├────────────────┼────────────────────────────────────────┤
│ submit         │ 폼을 보냄. **type 을 안 쓰면 이것** ⭐ │
├────────────────┼────────────────────────────────────────┤
│ button         │ 아무것도 안 함. 내가 붙인 일만 함      │
├────────────────┼────────────────────────────────────────┤
│ reset          │ 폼을 전부 비움                         │
└────────────────┴────────────────────────────────────────┘

⭐ form 안의 <button> 은 type 을 안 쓰면 submit 입니다.
  그냥 버튼으로 쓰려면 반드시 type="button" 을 쓰세요.
  이걸 모르면 "버튼 눌렀는데 화면이 새로고침됨" 을 평생 만납니다.

6. 검증 함수의 모양 (중요)

여기가 설계의 핵심입니다. 검증 함수는 이렇게 생겨야 합니다.

**값 하나를 받아서, 에러 메시지를 돌려준다. 문제가 없으면 빈 문자열.**

const checkName = (v) => {
  if (!v.trim()) return "이름을 입력하세요"
  if (v.trim().length < 2) return "2자 이상 입력하세요"
  return ""
}

왜 이 모양이 좋은가:

┌────────────────────────────────┬────────────────────────────┐
│ 방식                           │ 문제                       │
├────────────────────────────────┼────────────────────────────┤
│ 함수 안에서 DOM 을 직접 고친다 │ 재사용 못 함. 테스트 못 함 │
├────────────────────────────────┼────────────────────────────┤
│ true / false 만 돌려준다       │ 뭐가 틀렸는지 모름         │
├────────────────────────────────┼────────────────────────────┤
│ **메시지를 돌려준다**          │ 둘 다 됨. "" 는 falsy 니까 │
└────────────────────────────────┴────────────────────────────┘

⭐ if (checkName(v)) 는 "에러가 있으면" 이라는 뜻입니다.
  빈 문자열은 falsy 니까요. 05 에서 본 그 falsy 입니다.

그리고 검증 함수 안에서 화면을 건드리지 마세요. **검증 함수는 값만 봅니다.**
화면에 쓰는 건 다른 함수의 일입니다. 13번 항목에서 왜 그런지 나옵니다.

7. 언제 검사하나 (아주 중요)

이게 폼의 느낌을 가장 크게 바꿉니다.

┌────────────────┬────────┬─────────────────────────────┐
│ 시점           │ 이벤트 │ 느낌                        │
├────────────────┼────────┼─────────────────────────────┤
│ 타이핑하는 중  │ input  │ 첫 글자부터 빨간불. 짜증남  │
├────────────────┼────────┼─────────────────────────────┤
│ 칸을 떠날 때   │ blur   │ 적당함. 기본값으로 좋음     │
├────────────────┼────────┼─────────────────────────────┤
│ 보낼 때        │ submit │ 늦음. 하지만 반드시 해야 함 │
├────────────────┼────────┼─────────────────────────────┤
│ 한번 틀린 칸만 │ input  │ ⭐ 이게 제일 좋음           │
└────────────────┴────────┴─────────────────────────────┘

실전 조합은 이렇습니다.

1) submit 때 전부 검사           - 필수. 이건 빼면 안 됩니다
2) blur 때 그 칸만 검사          - 칸을 떠날 때 알려줌
3) 한번 에러가 난 칸은 그 뒤로 input 때마다 검사

3번이 "잘 만든 폼" 의 느낌을 만듭니다.
사용자가 고치는 즉시 빨간불이 꺼지니까요. 아직 안 틀린 칸은 조용히 있습니다.

· 아직 아무것도 안 한 칸     조용함
· 떠났는데 비어 있음         에러 켜짐
· 다시 들어와서 고치는 중    글자마다 다시 검사 -> 맞는 순간 꺼짐

8. 에러를 어디에 띄우나

말풍선을 껐으니 내가 그려야 합니다.

<div class="field">
  <label for="name">이름</label>
  <input id="name" name="name">
  <p class="err" data-for="name"></p>
</div>

$(".err[data-for=name]").textContent = msg
$("#name").classList.toggle("invalid", !!msg)

· 에러 칸은 **처음부터 HTML 에 있어야** 합니다. 매번 만들고 지우면 레이아웃이 들썩입니다.
· classList.toggle(클래스, 조건) - 07 에서 배운 두번째 인자입니다. if/else 가 사라집니다.
· 지울 때는 textContent = "" 입니다.

.err { color: #c00; font-size: 13px; min-height: 18px; }
input.invalid { border-color: #c00; }

⭐ min-height 가 중요합니다. 없으면 에러가 뜰 때마다 폼 전체가 아래로 밀립니다.
  칸이 10개면 10번 들썩입니다. 자리를 미리 비워두세요.

9. 자주 쓰는 검증들

┌───────────────┬─────────────────────────────┬──────────────────────────────┐
│ 검사          │ 코드                        │ 주의                         │
├───────────────┼─────────────────────────────┼──────────────────────────────┤
│ 빈 값         │ !v.trim()                   │ 공백만 넣은 것도 빈 값 ⭐    │
├───────────────┼─────────────────────────────┼──────────────────────────────┤
│ 길이          │ v.trim().length < 2         │                              │
├───────────────┼─────────────────────────────┼──────────────────────────────┤
│ 숫자인가      │ isNaN(Number(v))            │ "" 는 0 이 됩니다 ⭐         │
├───────────────┼─────────────────────────────┼──────────────────────────────┤
│ 정수인가      │ !Number.isInteger(+v)       │                              │
├───────────────┼─────────────────────────────┼──────────────────────────────┤
│ 범위          │ +v < 1 || +v > 120          │ 문자열이니 + 로 숫자화       │
├───────────────┼─────────────────────────────┼──────────────────────────────┤
│ select 미선택 │ !v                          │ <option value=""> 를 두면 됨 │
├───────────────┼─────────────────────────────┼──────────────────────────────┤
│ 체크박스      │ !el.checked                 │ value 가 아니라 checked ⭐   │
├───────────────┼─────────────────────────────┼──────────────────────────────┤
│ 라디오 그룹   │ !$('input[name=x]:checked') │ 하나도 안 골랐으면 null      │
├───────────────┼─────────────────────────────┼──────────────────────────────┤
│ 두 칸 비교    │ pw !== pw2                  │ 15번 항목 참고               │
├───────────────┼─────────────────────────────┼──────────────────────────────┤
│ 파일          │ !el.files.length            │ files 는 배열 같은 것        │
└───────────────┴─────────────────────────────┴──────────────────────────────┘

⭐ .trim() 을 빼먹으면 스페이스 하나가 통과합니다. 가장 흔한 구멍입니다.
⭐ 체크박스와 라디오는 .value 를 보면 안 됩니다.
  체크 여부와 무관하게 value 는 항상 있습니다. 봐야 하는 건 checked 입니다.
⭐ Number("") 는 0 입니다. NaN 이 아닙니다.
  그래서 빈 값 검사를 숫자 검사보다 **먼저** 해야 합니다.

10. 정규식 최소 세트

정규식은 깊이 들어가면 끝이 없습니다. 폼 검증에 쓰는 만큼만 봅니다.

┌────────┬────────────────┬─────────┬───────────────────┐
│ 기호   │ 뜻             │ 기호    │ 뜻                │
├────────┼────────────────┼─────────┼───────────────────┤
│ ^      │ 시작           │ +       │ 1개 이상          │
├────────┼────────────────┼─────────┼───────────────────┤
│ $      │ 끝             │ *       │ 0개 이상          │
├────────┼────────────────┼─────────┼───────────────────┤
│ .      │ 아무 글자 하나 │ ?       │ 0개 또는 1개      │
├────────┼────────────────┼─────────┼───────────────────┤
│ \d     │ 숫자           │ {3}     │ 정확히 3개        │
├────────┼────────────────┼─────────┼───────────────────┤
│ \D     │ 숫자 아님      │ {2,4}   │ 2~4개             │
├────────┼────────────────┼─────────┼───────────────────┤
│ \w     │ 영문 숫자 _    │ {2,}    │ 2개 이상          │
├────────┼────────────────┼─────────┼───────────────────┤
│ \s     │ 공백           │ |       │ 또는              │
├────────┼────────────────┼─────────┼───────────────────┤
│ [abc]  │ a b c 중 하나  │ ()      │ 묶음              │
├────────┼────────────────┼─────────┼───────────────────┤
│ [^abc] │ a b c 빼고     │ \\      │ 기호 자체를 쓸 때 │
├────────┼────────────────┼─────────┼───────────────────┤
│ [0-9]  │ 0부터 9까지    │ [가-힣] │ 한글 한 글자      │
└────────┴────────────────┴─────────┴───────────────────┘

⭐ ^ 와 $ 를 안 쓰면 "포함" 검사가 됩니다. 이게 제일 많이 틀리는 부분입니다.

/\d{3}/.test("abc123xyz")      // true   - 어딘가에 숫자 3개가 있다
/^\d{3}$/.test("abc123xyz")    // false  - 전체가 숫자 3개여야 한다

폼 검증은 거의 항상 ^...$ 입니다.
(2번에서 본 HTML 의 pattern 속성은 반대로 자동으로 전체 일치입니다)

쓰는 법은 하나만 알면 됩니다.

const re = /^010-\d{4}-\d{4}$/
re.test(v)        // true / false

실용 예:

한글 이름        /^[가-힣]{2,5}$/
전화번호         /^01[016789]-\d{3,4}-\d{4}$/
숫자만           /^\d+$/
영문숫자 ID      /^[a-zA-Z0-9]{4,12}$/
우편번호         /^\d{5}$/

비밀번호 (영문/숫자/특수 각각 1개 이상, 8자 이상):
/^(?=.*[a-zA-Z])$/
/^(?=.*[a-zA-Z])(?=.*\d)(?=.*[^a-zA-Z0-9]).{8,}$/

(?=...) 는 "앞을 내다보기" 입니다. 위치를 옮기지 않고 "뒤에 이런 게 있나" 만 봅니다.
그래서 세 조건을 겹쳐서 AND 로 쓸 수 있습니다. 이것만 알아두면 충분합니다.

11. 이메일은 정규식으로 하지 마세요

이메일 정규식을 검색하면 괴물 같은 걸 줍니다. 그걸 쓰면 안 됩니다.

· 완벽한 이메일 정규식은 사실상 불가능합니다. 규격이 허용하는 형태가 너무 많습니다
· 짧은 정규식은 멀쩡한 주소를 거부합니다
· 긴 정규식은 읽을 수 없고, 그래도 틀립니다

대신 브라우저에게 맡기세요.

<input type="email" id="email">

$("#email").validity.typeMismatch     // 브라우저가 판단해준다

공짜고, 나보다 정확합니다. 더 보고 싶으면 아주 느슨하게만 보태세요.

const checkEmail = (v) => {
  if (!v.trim()) return "이메일을 입력하세요"
  if (!v.includes("@")) return "이메일 형식이 아닙니다"
  return ""
}

⭐ "진짜 존재하는 주소인가" 는 형식 검사로 절대 알 수 없습니다.
  그건 메일을 보내봐야 압니다. 그래서 가입 확인 메일이 있는 거예요.

12. 값을 한번에 꺼내기 - FormData (05 복습)

칸이 8개면 $("#a").value 를 8번 쓰나요? 아닙니다.

    "값이 비어서 나오는데요?" 의 범인이 거의 이겁니다.

13. 전체 구조 (아주 중요)

여기가 08, 09, 10 과 같은 이야기입니다. **판단과 그리기를 나눕니다.**

const rules = {
  name:  v => !v.trim() ? "이름을 입력하세요" : "",
  email: v => !v.trim() ? "이메일을 입력하세요" : "",
  age:   v => !v ? "나이를 입력하세요" : "",
}

const showError = (name, msg) => { ... }      // 화면에 쓰기만
const validateField = (name) => { ... }       // 한 칸 검사하고 표시
const validateAll = () => { ... }             // 전부 검사, 통과 여부 반환

$("#f").addEventListener("submit", e => {
  e.preventDefault()
  if (!validateAll()) return
  // 통과 - 여기서 보낸다
})

세 함수의 역할이 겹치지 않습니다.

┌───────────────┬────────────────┬──────────────────┐
│ 함수          │ 하는 일        │ 안 하는 일       │
├───────────────┼────────────────┼──────────────────┤
│ rules         │ 값 -> 메시지   │ DOM 을 못 건드림 │
├───────────────┼────────────────┼──────────────────┤

├───────────────┼────────────────┼──────────────────┤
│ validateField │ 둘을 이어줌    │ 문구를 안 정함   │
├───────────────┼────────────────┼──────────────────┤
│ validateAll   │ 전부 돌리기    │ 문구를 안 정함   │
└───────────────┴────────────────┴──────────────────┘

⭐ 이게 08 의 save / draw / update, 09 와 10 의 render 와 같은 구조입니다.
  **판단하는 곳과 그리는 곳을 나눈다.** 매번 같은 이야기가 나오는 이유가 있습니다.

칸을 하나 추가할 때 rules 에 한 줄만 쓰면 되는지 보세요. 그러면 구조가 맞은 겁니다.

그리고 또 한번:

⭐⭐ **addEventListener 가 함수 안에 있으면 거의 항상 틀린 것입니다.**
    함수 안에는 부를 때마다 다시 해야 하는 일만 넣습니다.
    이벤트 등록은 한 번만 하면 됩니다.

validateField 안에 addEventListener 를 넣으면, 검사할 때마다 핸들러가 하나씩
더 붙습니다. 그러면 에러가 두 번, 세 번, 네 번 뜹니다.

14. 실시간 검증 + 디바운스 (08 복습)

아이디 중복 확인처럼 **서버에 물어봐야 하는** 검증이 있습니다.

$("#id").addEventListener("input", ...)    // 한 글자마다 요청?  안 됩니다

08 에서 한 디바운스가 여기서 또 쓰입니다.

let timer
$("#id").addEventListener("input", () => {
  clearTimeout(timer)
  timer = setTimeout(async () => {
    const res = await fetch("/check?id=" + $("#id").value)
    if (!res.ok) throw new Error("서버 오류")
    ...
  }, 300)
})

⭐ timer 가 핸들러 **밖에** 있는 것. 08 에서 짚은 그대로입니다.
  안에 넣으면 매번 새로 만들어져서 디바운스가 아예 안 됩니다.

그리고 비동기 검증은 순서가 꼬일 수 있습니다.
"ab" 의 답이 "abc" 의 답보다 늦게 도착할 수 있어요. 그러면 틀린 결과가 화면에 남습니다.
지금은 몰라도 되지만, 그래서 AbortController 가 있다는 것만 기억해두세요.
**그런데 input 이 유일한 방법은 아닙니다.** (노벨 님 질문, 2026-11-05)

"중복확인" 버튼을 두고 누를 때만 확인하는 방식도 완전히 정상입니다.
요청이 비싼 API 라면 오히려 이게 맞습니다.

<button type="button" id="checkId">중복확인</button>

⭐ type="button" 과 e.preventDefault() 는 세트가 아닙니다. 같은 문제를 푸는 두 방법입니다.

  type="submit" + e.preventDefault()    폼이 보내려는 걸 막는다
  type="button"                        애초에 안 보낸다. preventDefault 필요 없음

버튼 방식의 장점:

· 요청이 사용자가 누를 때만 간다. 디바운스가 필요 없다
· 경쟁 상태(먼저 보낸 응답이 늦게 오는 문제)가 아예 없다
· 코드가 짧다

⭐⭐ 그런데 버튼만으로는 안 끝납니다. 이 순서를 보세요.

  1) "novel2026" 입력 -> 중복확인 -> "사용 가능합니다"
  2) 사용자가 뒤에 7 을 붙여 "novel20267" 로 고친다
  3) 화면에는 아직 "사용 가능합니다" 가 떠 있다

3번이 거짓말입니다. 확인한 적 없는 아이디인데 초록불이 켜져 있어요.
그래서 값이 바뀌면 그 결과를 지워야 하고, 그걸 알려면 input 이벤트가 필요합니다.

$("#userid").addEventListener("input", () => { /* 확인 결과를 지운다 */ })

버튼 방식도 input 리스너가 결국 생깁니다. 다만 거기서 fetch 를 하지 않고
**상태만 지웁니다.** 15번 항목의 "두 칸이 서로를 본다" 와 같은 종류의 함정입니다.

그리고 상태가 하나 늘어납니다.

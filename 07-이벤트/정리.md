# 07 - 이벤트

## 1. 이벤트는 왜 필요한가

Day 06까지 만든 건 전부 **한 번 실행하고 끝**이었습니다.

```js
$("#title").textContent = "DOM 정복"
```

파일을 열면 위에서 아래로 쭉 실행되고, 그걸로 끝. 사용자가 버튼을 눌러도 아무 일도 안 일어납니다.

```
Day 06 : 페이지가 열릴 때 딱 한 번  ->  화면을 바꾼다
Day 07 : 사용자가 뭔가 할 때마다    ->  화면을 바꾼다
```

"할 때마다"를 만드는 게 이벤트입니다. 그리고 Day 08·09에서 "버튼 누르면 서버에 요청"이 되려면 **누르는 걸 감지하는 것**이 먼저 있어야 해요. 이벤트가 그 입구입니다.

## 2. addEventListener ⭐

```js
요소.addEventListener("이벤트이름", 실행할함수)
```

세 덩어리입니다. **누가 / 언제 / 뭘 할지.**

```js
$("#btn").addEventListener("click", () => {
  console.log("눌렸다")
})
```

- `$("#btn")` — 누가 (감시 대상)
- `"click"` — 언제 (이벤트 종류, **문자열**)
- `() => {...}` — 뭘 (핸들러 handler)

### 함수를 "넘기는" 것이지 "부르는" 게 아닙니다 ⭐⭐

여기서 제일 많이 틀립니다.

```js
btn.addEventListener("click", hello)     // 함수 자체를 넘김
btn.addEventListener("click", hello())   // 지금 당장 실행해버림
```

괄호를 붙이면 **그 자리에서 실행되고, 그 반환값(보통 undefined)이 등록**됩니다. 클릭해도 아무 일이 안 일어나요. 에러도 안 납니다.

Day 03의 "함수 이름은 함수 그 자체, 괄호는 실행"이 여기서 실제로 터집니다.

```js
const hello = () => console.log("안녕")

btn.addEventListener("click", hello)         // 누를 때마다 "안녕"
btn.addEventListener("click", hello())       // 로드 즉시 "안녕" 한 번, 클릭은 무반응
btn.addEventListener("click", () => hello()) // 이건 됨 (감싸서 넘김)
```

인자를 넘겨야 할 때만 세 번째 모양을 씁니다.

```js
btn.addEventListener("click", () => greet("노벨"))
```

### onclick 이라는 옛날 방식

```js
btn.onclick = () => console.log("A")
btn.onclick = () => console.log("B")   // A가 사라짐 - 덮어쓰기
```

`onclick`은 **속성**이라 하나만 들어갑니다. `addEventListener`는 **여러 개를 쌓을 수 있어요.**

```js
btn.addEventListener("click", () => console.log("A"))
btn.addEventListener("click", () => console.log("B"))   // A, B 둘 다 실행
```

Day 06의 `className` vs `classList.add`와 완전히 같은 구도입니다. 덮어쓰기냐 추가냐.

▎ HTML에 `<button onclick="doIt()">`이라고 쓰는 방식도 있는데, 화면(HTML)과 동작(JS)이 섞여서 안 씁니다.

### 떼기

```js
const onClick = () => console.log("한 번만")
btn.addEventListener("click", onClick)
btn.removeEventListener("click", onClick)   // 같은 함수를 넘겨야 떼짐
```

화살표를 그 자리에 바로 쓰면 **못 뗍니다.** 모양이 같아도 다른 함수거든요.

```js
btn.addEventListener("click", () => console.log("x"))
btn.removeEventListener("click", () => console.log("x"))   // 안 떨어짐
```

한 번만 실행하고 싶으면 이게 더 쉽습니다.

```js
btn.addEventListener("click", onClick, { once: true })
```

## 3. 이벤트 객체 - 핸들러의 매개변수 ⭐⭐

핸들러는 매개변수를 하나 받습니다. 브라우저가 **무슨 일이 일어났는지**를 객체로 담아서 넣어줘요.

```js
btn.addEventListener("click", (e) => {
  console.log(e)          // PointerEvent {...}
  console.log(e.type)     // "click"
  console.log(e.target)   // 실제로 눌린 요소
})
```

`e`는 그냥 관례적인 이름입니다 (event). 안 쓸 거면 안 받아도 돼요.

### target 과 currentTarget ⭐⭐⭐

이 둘의 차이가 Day 07의 핵심입니다.

```
target        - 실제로 눌린 놈 (제일 안쪽)
currentTarget - 리스너가 붙어 있는 놈
```

```html
<div id="card">
  <h3>키보드</h3>
  <button class="buy">구매</button>
</div>
```

```js
$("#card").addEventListener("click", (e) => {
  console.log(e.target)         // 구매 버튼을 눌렀으면 <button>
  console.log(e.currentTarget)  // 항상 <div id="card">
})
```

`<h3>`를 누르면 `target`은 `<h3>`, `currentTarget`은 여전히 `#card`입니다.

▎ 헷갈리면 이렇게 외우세요. **target은 손가락이 닿은 곳, currentTarget은 귀를 대고 있는 곳.**

## 4. this 와 화살표 함수 ⚠️

일반 함수로 쓰면 `this`가 `currentTarget`이 됩니다.

```js
btn.addEventListener("click", function () {
  console.log(this)   // <button> - currentTarget과 같음
})
```

**화살표 함수는 this를 안 가집니다.**

```js
btn.addEventListener("click", () => {
  console.log(this)   // window - 엉뚱한 것
})
```

Day 03에서 "화살표 함수는 짧은 버전"이라고만 배웠는데, 사실 `this` 동작이 다릅니다. 이게 유일한 실질적 차이예요.

**그래서 이 수업에서는 `this`를 안 씁니다.** `e.currentTarget`을 쓰면 화살표 함수든 아니든 똑같이 동작하니까요.

```js
btn.addEventListener("click", (e) => {
  e.currentTarget.classList.add("hi")   // 항상 안전
})
```

▎ 남의 코드에서 `this`를 만나면 "아 currentTarget이구나" 하고 읽으시면 됩니다.

## 5. 여러 개에 붙이기 - Day 06이 여기서 쓰입니다

리스너는 **요소 하나에 하나씩** 붙습니다. 여러 개면 돌려야 해요.

```js
$$(".buy").addEventListener(...)   // 배열에는 그런 거 없음
```

Day 06의 `$$(".desc").textContent = "야호"`와 똑같은 함정입니다. **여러 개를 잡았으면 반드시 돌려야 한다.**

```js
$$(".buy").forEach(btn => {
  btn.addEventListener("click", (e) => {
    console.log("눌림")
  })
})
```

### 누른 버튼의 상품 찾기 - closest ⭐⭐⭐

Day 06의 8-4가 그대로 나옵니다.

```js
$$(".buy").forEach(btn => {
  btn.addEventListener("click", (e) => {
    const card = e.currentTarget.closest(".card")
    const name = card.querySelector(".name").textContent
    console.log(name + " 담김")
  })
})
```

`closest`는 **자기 자신부터 위로 올라가며** 조건에 맞는 첫 조상을 찾습니다. 버튼이 어느 카드에 속했는지 알아내는 표준 수법이에요. 장바구니, 삭제 버튼, 수량 조절 - 전부 이 모양입니다.

## 6. 버블링 ⭐⭐

이벤트는 **안에서 바깥으로 퍼져 나갑니다.**

```html
<div id="outer">
  <div id="middle">
    <button id="inner">눌러</button>
  </div>
</div>
```

`#inner`를 누르면:

```
inner  ->  middle  ->  outer  ->  body  ->  html  ->  document
```

셋 다에 리스너를 붙여두면 **세 개가 전부 실행**됩니다. 순서는 안쪽부터예요.

```js
outer.addEventListener("click", () => console.log("outer"))
middle.addEventListener("click", () => console.log("middle"))
inner.addEventListener("click", () => console.log("inner"))

// inner 클릭 ->  inner, middle, outer  순으로 찍힘
```

물방울이 아래에서 위로 올라간다고 해서 버블링(bubbling)입니다.

### 멈추기

```js
inner.addEventListener("click", (e) => {
  e.stopPropagation()   // 여기서 끝. middle, outer로 안 올라감
})
```

▎ 남용하지 마세요. 위쪽에서 "아무 데나 누르면 메뉴 닫기" 같은 걸 하고 있으면 그게 죽습니다. 진짜 필요할 때만.

## 7. 이벤트 위임 (delegation) ⭐⭐⭐

버블링을 **역이용**하는 기술입니다. 오늘의 하이라이트예요.

문제 상황부터 봅시다.

```js
$$(".del").forEach(btn => {
  btn.addEventListener("click", (e) => e.target.closest("li").remove())
})

// 나중에 새 항목을 추가하면?
list.append(nl("li", { textContent: "새 할 일" }))   // 이 삭제 버튼은 동작 안 함
```

`forEach`는 **그 순간 존재하던 것들**에만 붙였습니다. 나중에 생긴 요소에는 리스너가 없어요.

해결: **부모 하나에만 붙이고, target으로 구분합니다.**

```js
$("#todoList").addEventListener("click", (e) => {
  if (!e.target.classList.contains("del")) return   // 삭제 버튼이 아니면 무시
  e.target.closest("li").remove()
})
```

부모는 처음부터 있으니까, 자식이 **나중에 몇 개가 생기든 전부 동작**합니다. 리스너도 100개가 아니라 1개고요.

```
개별 등록 : 항목 100개 -> 리스너 100개, 새 항목은 수동 등록
위임      : 항목 100개 -> 리스너  1개, 새 항목도 자동으로 동작
```

`closest`로 쓰는 게 더 안전합니다. 버튼 안에 아이콘 같은 게 들어있으면 `e.target`이 아이콘일 수 있거든요.

```js
list.addEventListener("click", (e) => {
  const btn = e.target.closest(".del")
  if (!btn) return
  btn.closest("li").remove()
})
```

▎ **`if (!___) return`으로 빠져나가는 모양**을 기억하세요. 위임 핸들러의 첫 줄은 거의 항상 이겁니다.

## 8. preventDefault - 브라우저 기본 동작 막기 ⭐⭐

어떤 요소는 **브라우저가 알아서 하는 짓**이 있습니다.

```
<a href="...">           클릭하면 그 주소로 이동
<form>                   submit하면 페이지를 새로고침하며 전송
<input type="checkbox">  클릭하면 체크 표시가 바뀜
```

이걸 막는 게 `e.preventDefault()`입니다.

```js
$("#link").addEventListener("click", (e) => {
  e.preventDefault()          // 이동 안 함
  console.log("막았다")
})
```

### form 이 제일 중요합니다 ⭐⭐⭐

Day 09(PHP 연동)의 출발점이에요.

```js
$("#joinForm").addEventListener("submit", (e) => {
  e.preventDefault()          // 이게 없으면 페이지가 새로고침됨
  const nick = $("#nickInput").value
  console.log(nick)
})
```

`preventDefault()`를 빼면 페이지가 **통째로 새로고침**되면서 콘솔이 지워집니다. "분명 console.log를 썼는데 아무것도 안 보인다"의 90%가 이겁니다.

```
전통 방식  : form 전송 -> 페이지 새로고침 -> PHP가 새 HTML을 내려줌
지금 방식  : preventDefault -> JS가 값을 읽음 -> fetch로 PHP에 보냄 -> 화면 일부만 갱신
```

Day 09에서 할 게 아래쪽입니다. 그 첫 줄이 `e.preventDefault()`예요.

### submit 은 form 에 붙입니다

버튼에 `click`으로 붙이면 안 됩니다. 엔터키로 제출하는 경우를 놓치거든요.

```js
$("#joinForm").addEventListener("submit", ...)   // O
$("#joinBtn").addEventListener("click", ...)     // X - 엔터 제출을 못 잡음
```

▎ `<button>`은 form 안에서 기본이 `type="submit"`입니다. 제출용이 아니면 `type="button"`을 꼭 적으세요.

## 9. 자주 쓰는 이벤트

```
click        눌렀을 때
input        입력값이 바뀔 때마다 (글자 하나하나)
change       다 바꾸고 포커스가 떠날 때 / select·checkbox는 즉시
submit       form 제출
keydown      키를 누를 때  (e.key 로 어떤 키인지)
mouseenter   마우스가 올라올 때
DOMContentLoaded   HTML을 다 읽었을 때
```

### input 과 change ⭐

```js
live.addEventListener("input",  e => console.log("input:",  e.target.value))
live.addEventListener("change", e => console.log("change:", e.target.value))
```

"abc"를 치면:

```
input: a
input: ab
input: abc        <- 글자마다
(다른 데 클릭)
change: abc       <- 한 번만
```

실시간 검색·글자수 세기는 `input`, 다 입력한 뒤 처리는 `change`입니다.
`select`와 `checkbox`는 `change`를 쓰세요.

### 체크박스는 value 가 아니라 checked

```js
agree.addEventListener("change", e => {
  console.log(e.target.checked)   // true / false
  console.log(e.target.value)     // "on" - 쓸모없음
})
```

### keydown

```js
input.addEventListener("keydown", (e) => {
  if (e.key !== "Enter") return
  console.log("엔터!")
})
```

`e.key`는 `"Enter"`, `"Escape"`, `"a"`, `"ArrowUp"` 같은 문자열입니다.

▎ 옛날 코드의 `e.keyCode === 13`은 폐기됐습니다. `e.key`를 쓰세요.

### DOMContentLoaded

Day 06 6번에서 예고한 겁니다.

```js
document.addEventListener("DOMContentLoaded", () => {
  // 여기 안은 HTML이 전부 준비된 뒤에 실행됨
})
```

`<script>`를 `</body>` 직전에 두면 사실 필요 없습니다. `<head>`에 둬야 할 때 쓰는 것이고, 요즘은 `<script defer>`가 더 간단해요.

## 10. lib.js 3번째 줄 해부 - nl ⭐⭐

드디어 씁니다.

```js
const nl = (a, t) => Object.assign(document.createElement(a), t)
```

- `a` - 태그 이름 (`"li"`, `"div"`)
- `t` - 속성들을 담은 객체
- `Object.assign(대상, 출처)` - 출처의 속성을 대상에 **복사해 넣고 대상을 반환**

원래 이렇게 써야 하는 걸

```js
const li = document.createElement("li")
li.textContent = "새 할 일"
li.className = "item"
```

한 줄로 줄인 겁니다.

```js
const li = nl("li", { textContent: "새 할 일", className: "item" })
```

Day 05의 **객체 단축 속성**과 Day 03의 **화살표 함수**가 여기서 합쳐집니다.

### 화면에 붙이기

만들기만 하면 **메모리에만 있고 화면엔 안 보입니다.** 붙여야 해요.

```js
list.append(li)         // 맨 뒤에 (여러 개 가능, 문자열도 됨)
list.prepend(li)        // 맨 앞에
li.remove()             // 자기 자신 삭제
list.innerHTML = ""     // 자식 전부 비우기
```

```js
$("#todoList").append(
  nl("li", { textContent: "공부하기" })
)
```

### innerHTML += 는 쓰지 마세요 ⚠️

```js
list.innerHTML += "<li>새 할 일</li>"   // X
```

전체를 문자열로 만들어 **싹 다시 그립니다.** 그러면:

1. 기존 요소에 붙여둔 **리스너가 전부 날아갑니다**
2. 입력 중이던 값, 체크 상태가 초기화됩니다
3. 사용자 입력이 섞이면 `<script>`까지 실행됩니다 (Day 06 7번)

`append` + `nl`을 쓰세요.

## 12. PHP와 비교

PHP는 **요청이 올 때 한 번 돌고 죽습니다.** 사용자가 버튼을 눌러도 PHP는 모르죠. 알려면 페이지를 새로 요청해야 합니다.

```
PHP  : 클릭 -> 서버에 요청 -> 페이지 전체를 다시 받음  (느리고 깜빡임)
JS   : 클릭 -> 그 자리에서 화면 수정                   (즉시)
```

Day 08·09에서 이 둘을 붙입니다.

```
클릭 감지(Day 07) -> fetch로 PHP 호출(Day 08) -> 받은 JSON으로 화면 갱신(Day 06)
```

Day 07은 그 **첫 칸**입니다. 이벤트가 없으면 시작 자체가 안 돼요.

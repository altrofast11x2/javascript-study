# 10 - 애니메이션
1. 애니메이션은 "빠르게 다시 그리기"입니다

영화도 만화도 원리가 같습니다. 조금씩 다른 그림을 빠르게 넘기면 눈이 움직임으로 착각해요.

1초에 그림 60장  ->  부드럽다
1초에 그림 10장  ->  뚝뚝 끊긴다

그림 한 장을 프레임(frame) 이라고 하고, 1초에 몇 장인지를 FPS 라고 합니다.
대부분 모니터가 초당 60번 화면을 다시 그립니다.

그래서 애니메이션 코드는 전부 이 모양입니다.

지우고 -> 값을 조금 바꾸고 -> 다시 그리고 -> 반복

Day 09 에서 만든 render() 에 "조금 바꾸고" 와 "반복" 이 붙은 것뿐입니다.

2. 두 갈래 - 섞이지 않습니다

┌────────┬─────────────┬─────────────────────────┬──────────────────────┐
│        │ 움직이는 것 │ 도구                    │ 쓰는 곳              │
├────────┼─────────────┼─────────────────────────┼──────────────────────┤
│ canvas │ 픽셀        │ requestAnimationFrame   │ 그래프, 게임, 시각화 │
│ CSS    │ 요소        │ transition / @keyframes │ 버튼, 메뉴, 모달     │
└────────┴─────────────┴─────────────────────────┴──────────────────────┘

완전히 다른 도구입니다. 3~12 번이 canvas, 13~17 번이 CSS 입니다.
실제 웹사이트에서 보는 움직임의 대부분은 CSS 입니다.
canvas 는 그림을 직접 그려야 할 때만 씁니다.

3. requestAnimationFrame - 반복의 도구

function loop() {
  console.log("한 프레임")
  requestAnimationFrame(loop)     // "다음 화면 갱신 때 나를 또 불러줘"
}
loop()                            // 첫 발만 밀어주면

예약이 한 번에 하나씩입니다. loop 안에서 또 예약하니까 계속 이어지는 겁니다.
예약을 안 하면 거기서 끝납니다.

loop() 호출 -> 실행 -> 다음 프레임 예약
                          실행 -> 다음 프레임 예약
                                    실행 -> ...

이름이 길어서 rAF 라고 줄여 부르기도 합니다.

4. setInterval 과 뭐가 다른가 (중요)

setInterval(loop, 16)          // 16ms 마다 - 화면과 상관없이
requestAnimationFrame(loop)    // 화면을 다시 그리기 "직전"에

┌──────────────┬───────────────────────┬───────────────────────┐
│              │ setInterval           │ requestAnimationFrame │
├──────────────┼───────────────────────┼───────────────────────┤
│ 호출 시점    │ 시간 되면 무조건      │ 화면 갱신 직전        │
│ 화면과 박자  │ 안 맞음 -> 끊겨 보임  │ 맞음 -> 부드러움      │
│ 탭을 숨기면  │ 계속 돔 (배터리 낭비) │ 멈춤                  │
│ 120Hz 모니터 │ 그대로 60번           │ 120번 (알아서 맞춤)   │
│ 밀렸을 때    │ 몰아서 실행           │ 건너뜀                │
└──────────────┴───────────────────────┴───────────────────────┘

박자가 안 맞는다는 게 핵심입니다. 화면은 16.7ms 마다 갱신되는데
setInterval 이 16ms 마다 그리면, 어떤 프레임은 두 번 그려지고
어떤 프레임은 안 그려져서 미세하게 떨립니다.

애니메이션         ->  requestAnimationFrame
1초마다 시계 갱신  ->  setInterval

5. 루프 안에서 하는 일은 항상 넷

function loop() {
  ctx.clearRect(0, 0, w, h)       // (1) 지우고
  x += 2                          // (2) 값을 바꾸고
  draw()                          // (3) 지금 값으로 그리고
  requestAnimationFrame(loop)     // (4) 다음 프레임 예약
}

(1) 을 빼먹으면 지나간 자리가 전부 남아 선이 그어집니다.
순서가 중요합니다. (2) 를 (3) 뒤에 두면 한 프레임 늦게 반영됩니다.

6. 프레임 기반 vs 시간 기반 (Day 10 에서 제일 중요)

x += 2        // "한 프레임에 2픽셀"

멀쩡해 보이는데 모니터마다 속도가 달라집니다.

60Hz  모니터  ->  초당 120픽셀
120Hz 모니터  ->  초당 240픽셀      같은 코드인데 2배 빠름
30fps 로 버벅 ->  초당  60픽셀      절반으로 느려짐

게임에서 "주사율 높으면 캐릭터가 빨라지는" 버그가 이겁니다.

해결 - 흐른 시간을 곱합니다.
requestAnimationFrame 은 콜백에 현재 시각을 넣어줍니다.

let prev = 0

function loop(now) {              // now 가 자동으로 들어옴 (단위: ms)
  const dt = (now - prev) / 1000  // 지난 프레임 이후 흐른 "초"
  prev = now

  x += 120 * dt                   // "초당 120픽셀"

  requestAnimationFrame(loop)
}
requestAnimationFrame(loop)

dt (delta time) 를 곱하면 "프레임당 얼마" 가 "초당 얼마" 로 바뀝니다.

60Hz   dt = 0.0167  ->  120 x 0.0167 = 2px/프레임  x 60프레임  = 120px/초
120Hz  dt = 0.0083  ->  120 x 0.0083 = 1px/프레임  x 120프레임 = 120px/초

어느 모니터에서도 같은 속도. 이게 애니메이션의 기본기입니다.

첫 프레임 주의 - prev 가 0 이면 dt 가 엄청나게 커져서 물체가 순간이동합니다.
첫 호출에서 prev = now 만 하고 넘기세요.

7. 끝이 있는 애니메이션 - 진행도

공이 계속 움직이는 건 끝이 없지만,
"0.8초 동안 막대가 자라나기" 처럼 끝이 있는 것도 있습니다.
그건 dt 대신 진행도로 합니다.

const dur = 800                                  // 0.8초
let start = null

function loop(now) {
  if (start === null) start = now
  const t = Math.min((now - start) / dur, 1)     // 0 -> 1 로 가는 값

  draw(t)                                        // t 를 받아서 그림

  if (t < 1) requestAnimationFrame(loop)         // 1 되면 멈춤
}

t 가 0 에서 1 까지 가는 동안 그림이 변합니다.
Math.min(..., 1) 로 1 을 넘지 않게 묶는 게 중요합니다.

Day 09 bar.html 에서 progress += 0.002 로 했는데 그건 프레임 기반이라
모니터에 따라 달라집니다. "시작 시각과 지금 시각의 차" 로 바꾸면 항상 0.8초입니다.

8. easing - 움직임의 성격

t 를 그대로 쓰면 일정한 속도입니다. 기계처럼 보입니다.

const linear    = t => t
const easeOut   = t => 1 - Math.pow(1 - t, 3)
const easeIn    = t => t * t * t
const easeInOut = t => t < .5 ? 4*t*t*t : 1 - Math.pow(-2*t + 2, 3) / 2

┌───────────┬────────────────────────┬─────────────────┐
│           │ 느낌                   │ 쓰는 곳         │
├───────────┼────────────────────────┼─────────────────┤
│ linear    │ 기계적                 │ 회전, 무한 반복 │
│ easeOut   │ 쑥 나와서 부드럽게 섬  │ 대부분          │
│ easeIn    │ 천천히 출발해서 빨라짐 │ 사라질 때       │
│ easeInOut │ 양쪽 다 부드럽게       │ 큰 이동         │
└───────────┴────────────────────────┴─────────────────┘

거의 easeOut 입니다. 현실에서 물체는 마찰로 서서히 멈추니까 눈에 자연스럽습니다.

draw(easeOut(t))     // t 자리에 가공한 값을 넣는다

9. lerp - 두 줄짜리 easing

진행도 없이, 목표값을 향해 계속 따라가게 하는 방법입니다.

x += (목표x - x) * 0.1       // 매 프레임 남은 거리의 10% 씩

남은 거리 100  ->  10 이동
남은 거리  90  ->   9 이동
남은 거리  81  ->   8 이동   ... 점점 느려짐

처음엔 빠르고 가까워지면 느려져서 저절로 easing 이 됩니다.
start, dur, progress 를 안 써도 됩니다.

목표가 계속 바뀌는 것    ->  lerp       (마우스 따라오기, 값 갱신)
정해진 시간에 끝나는 것  ->  progress   (막대 자라나기)

0.1 을 키우면 빨리 따라붙고, 줄이면 느긋해집니다. 실무에서 아주 많이 씁니다.

10. 멈추기와 다시 시작 - cancelAnimationFrame

let id = null

function loop() {
  ...
  id = requestAnimationFrame(loop)     // 번호표를 받아둔다
}

id = requestAnimationFrame(loop)       // 시작
cancelAnimationFrame(id)               // 정지

setTimeout / clearTimeout 과 똑같은 짝입니다. 디바운스에서 쓴 그 패턴입니다.

흔한 버그 - 루프가 두 개 돌기

start.onclick = () => loop()      // X  두 번 누르면?

루프가 두 개 생겨서 속도가 2배가 됩니다. 세 번 누르면 3배입니다.
막으려면 둘 중 하나입니다.

start.onclick = () => {
  cancelAnimationFrame(id)        // (1) 기존 걸 취소하고 새로 시작
  id = requestAnimationFrame(loop)
}

let running = false
start.onclick = () => {
  if (running) return             // (2) 이미 돌고 있으면 무시
  running = true
  loop()
}

11. 여러 개 움직이기

하나와 백 개가 구조상 같습니다. 객체 배열로 두면 됩니다.

const balls = [
  { x: 50, y: 50, vx: 120, vy:  80, r: 10, color: "tomato" },
  { x: 90, y: 20, vx: -90, vy: 140, r: 14, color: "gold" },
]

function loop(now) {
  const dt = ...
  ctx.clearRect(0, 0, w, h)

  balls.forEach(b => {
    b.x += b.vx * dt
    b.y += b.vy * dt

    ctx.beginPath()
    ctx.fillStyle = b.color
    ctx.arc(b.x, b.y, b.r, 0, Math.PI * 2)
    ctx.fill()
  })

  requestAnimationFrame(loop)
}

vx, vy 가 속도입니다. velocity x / y 입니다.
공 100개로 늘려도 코드는 그대로고 배열만 커집니다.

12. 벽에 튕기기

if (b.x - b.r < 0 || b.x + b.r > w) b.vx = -b.vx     // 좌우 벽
if (b.y - b.r < 0 || b.y + b.r > h) b.vy = -b.vy     // 위아래 벽

부호만 뒤집으면 됩니다. 오른쪽으로 가던 게 왼쪽으로 가는 겁니다.

b.r 을 더하고 빼는 이유 - 공의 중심이 아니라 가장자리가 벽에 닿아야 하니까요.
안 하면 공이 벽에 반쯤 파묻힌 뒤에 튕깁니다.

벽에 끼는 버그 - 속도가 빠르면 한 프레임에 벽을 많이 넘어가서,
부호를 뒤집어도 다음 프레임에 또 조건이 참이 돼 덜덜 떱니다.
위치를 벽 안쪽으로 되돌려주면 해결됩니다.

=================== 여기부터 CSS 애니메이션 ===================

canvas 랑 아무 상관없습니다. 요소를 움직일 때 쓰는 완전히 다른 도구입니다.

13. transition - 값이 바뀔 때 부드럽게

.box {
  background: tomato;
  transition: transform .3s ease-out, background .3s;
}
.box:hover {
  transform: translateX(20px) scale(1.1);
  background: gold;
}

JS 가 한 줄도 없습니다.
transition 은 "이 속성이 바뀌면 갑자기 바꾸지 말고 0.3초에 걸쳐 바꿔라" 라는 뜻입니다.

transition: 어떤속성  시간  곡선      지연시간;
            transform  .3s  ease-out  .1s

JS 에서 쓰려면 클래스만 토글하면 됩니다.

box.classList.toggle("open")     // 나머지는 CSS 가 알아서

transition: all .3s 는 쓰지 마세요. 모든 속성을 감시해서 느려지고,
의도치 않은 것까지 애니메이션됩니다. 바꿀 속성을 명시하세요.

14. @keyframes - 여러 단계

transition 은 "A 에서 B 로" 한 번입니다. 여러 단계나 반복은 @keyframes 입니다.

@keyframes bounce {
  0%   { transform: translateY(0) }
  50%  { transform: translateY(-30px) }
  100% { transform: translateY(0) }
}

.ball {
  animation: bounce 1s ease-in-out infinite;
}

animation: 이름   시간  곡선  반복횟수   방향       채우기;
           bounce 1s    ease  infinite  alternate  forwards

┌───────────────────────────┬───────────────────────────────────────┐
│ 속성                      │ 뜻                                    │
├───────────────────────────┼───────────────────────────────────────┤
│ animation-iteration-count │ 반복 횟수 (infinite 가능)             │
│ animation-direction       │ alternate 면 갔다가 되돌아옴          │
│ animation-fill-mode       │ forwards 면 끝난 상태를 유지          │
│ animation-delay           │ 시작 전 대기                          │
│ animation-play-state      │ paused / running - JS 로 멈출 수 있음 │
└───────────────────────────┴───────────────────────────────────────┘

fill-mode: forwards 를 모르면 당황합니다. 기본값은 애니메이션이 끝나면
원래 상태로 되돌아갑니다. 끝난 모습을 유지하려면 꼭 넣어야 합니다.

15. transform 과 opacity 만 쓰세요 (중요)

/* X 느립니다 */
.box { transition: left .3s; }
.box.on { left: 200px; }

/* O 빠릅니다 */
.box { transition: transform .3s; }
.box.on { transform: translateX(200px); }

왜 다른가 - 브라우저가 화면을 만드는 단계가 이렇습니다.

(1) 레이아웃   어디에 얼마나 크게 놓을지 계산
(2) 페인트     색칠
(3) 합성       레이어를 겹쳐서 화면에 올림

left / width / top / margin 을 바꾸면 (1) 부터 다시 합니다.
그 요소뿐 아니라 주변 요소 위치까지 다시 계산합니다.
프레임마다 그걸 하면 버벅입니다.

transform 과 opacity 는 (3) 만 합니다.
이미 그려진 걸 옮기거나 투명도만 바꾸는 거라 그래픽카드가 처리합니다.

움직임  ->  transform: translate()
크기    ->  transform: scale()        (width 가 아니라!)
회전    ->  transform: rotate()
사라짐  ->  opacity

이 네 개로 거의 다 됩니다.

17. 멈춤을 선호하는 사용자

애니메이션이 불편한 사람이 있습니다.
운영체제에 "움직임 줄이기" 설정이 있고, CSS 로 읽을 수 있습니다.

@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}

다섯 줄짜리 배려입니다. 실무에서는 넣는 게 기본입니다.

=================== 외울 것 ===================

canvas
  requestAnimationFrame     루프. setInterval 쓰지 말 것
  dt 를 곱한다              모니터와 무관한 속도
  progress 0->1 + easing    끝이 있는 애니메이션
  lerp                      목표를 따라가는 애니메이션
  cancelAnimationFrame      멈추기. 두 번 시작 주의
  객체 배열                 여러 개

CSS
  transition                값이 바뀔 때. 클래스 토글로 조작
  @keyframes                여러 단계, 반복. fill-mode: forwards 주의
  transform / opacity 만    나머지는 느리다
더 배운거.

1. 왜 비동기인가

지금까지 짠 코드는 전부 즉시 끝났습니다. map 돌리든 DOM 바꾸든 눈 깜짝할 새죠. 그런데 이건 다릅니다.

const data = 서버에서_상품목록_가져오기()   // 0.3초? 3초? 안 올 수도?

서버는 내 컴퓨터가 아닙니다. 요청이 인터넷을 타고 갔다 와야 해요. 만약 JS가 그 답을 기다리면서 멈춰 있으면 어떻게 될까요?

요청 보냄 ──────── 3초 ──────── 응답 옴
           ↑ 이 3초 동안 버튼도 안 눌리고 스크롤도 안 되고 화면이 얼어붙음

브라우저의 JS는 일꾼이 한 명입니다. 그 일꾼이 서버 답장을 기다리며 서 있으면 아무것도 못 해요. 그래서 이렇게 합니다.

▎ "일단 시켜놓고 다른 일 하다가, 다 되면 그때 처리한다."

이게 비동기입니다. Day 08의 전부예요.

2. 코드 순서 ≠ 실행 순서 ⭐⭐

console.log("1")
setTimeout(() => console.log("2"), 0)   // 0초인데도!
console.log("3")

1
3
2   ← 0초로 줬는데 맨 마지막

setTimeout은 "지금 실행"이 아니라 "나중에 실행해줘"라고 예약만 하고 즉시 넘어갑니다.
0초여도 마찬가지예요. 지금   약된 게 실행됩니다.

[지금 할 일]  console.log("1") -> setTimeout 예약 -> console.log("3")

[대기줄]                          () => console.log("2")
                                       ↓
           지금 할 일이 다 끝났다 -> 대기줄에서 하나 꺼내서 실행

"비동기 코드는 항상 나중" — 에서 직접 맞혀보실 겁니다.

5. async / await ⭐⭐⭐

.then을 계속 이어붙이는 것도 길어집니다. 그래서 "기다리는 것처럼 보이게" 쓰는 문법이 나왔어요.

// then 버전
const f = () => {
  wait1().then(값 => console.log(값))
}

// await 버전 — 완전히 같은
const f = async () => {
  const 값 = await wait1()
  console.log(값)
}

await는 "이 진동벨이 울릴 때까지 여기서 기다렸다가 결과를 꺼내라" 입니다. 위아래로 읽히니까 동기 코드처럼 보이죠. 이게 요즘 표준입니다.

# 12 - localStorage

1. localStorage 는 브라우저에 남는 메모장입니다

지금까지 만든 건 전부 새로고침하면 사라졌습니다.
Day 11 폼에 값을 다 채워놓고 F5 를 누르면 빈 폼이 나오죠.

변수는 페이지가 살아있는 동안만 삽니다.
localStorage 는 브라우저가 디스크에 적어둡니다. 그래서 남습니다.

  변수          페이지를 떠나면 사라진다
  localStorage  내가 지울 때까지 남는다

브라우저를 닫아도, 컴퓨터를 꺼도 남아 있습니다.
"저장 버튼이 없는데도 내용이 남아있는" 사이트들이 이걸 씁니다.


2. 비슷한 게 세 개 있습니다

┌────────────────┬──────────────┬────────┬─────────────┬───────────────────────────┐
│                │ 사는 기간    │ 용량   │ 서버로 가나 │ 쓰는 곳                   │
├────────────────┼──────────────┼────────┼─────────────┼───────────────────────────┤
│ localStorage   │ 지울 때까지  │ 약 5MB │ 안 간다     │ 설정, 찜 목록, 임시 저장  │
│ sessionStorage │ 탭 닫으면 끝 │ 약 5MB │ 안 간다     │ 입력 중인 폼, 마법사 단계 │
│ 쿠키           │ 만료일까지   │ 약 4KB │ 매 요청마다 │ 로그인 세션 (서버가 쓴다) │
└────────────────┴──────────────┴────────┴─────────────┴───────────────────────────┘

쿠키는 매 요청마다 서버로 따라갑니다. 그래서 4KB 밖에 안 되고,
그래서 로그인 세션에 씁니다. 우리가 직접 만질 일은 거의 없습니다.

localStorage 와 sessionStorage 는 쓰는 법이 완전히 똑같습니다.
사는 기간만 다릅니다. 아래 설명은 둘 다에 해당합니다.


3. 메서드는 네 개뿐입니다

┌─────────────────┬───────────────────────┬─────────────────┐
│ 쓰는 법         │ 하는 일               │ 없을 때         │
├─────────────────┼───────────────────────┼─────────────────┤
│ setItem(키, 값) │ 저장한다 (덮어쓴다)   │ -               │
│ getItem(키)     │ 꺼낸다                │ null            │
│ removeItem(키)  │ 그 키만 지운다        │ 조용히 넘어간다 │
│ clear()         │ 이 사이트 전부 지운다 │ -               │
│ length          │ 저장된 개수           │ 0               │
│ key(n)          │ n 번째 키 이름        │ null            │
└─────────────────┴───────────────────────┴─────────────────┘

위에서 아래로 차례대로 실행한 것입니다.

  localStorage.setItem("theme", "dark")   // 넣었다
  localStorage.getItem("theme")           // "dark"   있으니까 값이 나온다
  localStorage.removeItem("theme")        // 지웠다        <- 여기서 답이 바뀐다
  localStorage.getItem("theme")           // null     없으니까 null 이 나온다

2번째 줄과 4번째 줄은 글자가 똑같은데 답이 다릅니다.
사이에 지우는 줄이 끼어 있기 때문입니다.

getItem 은 "그 순간 저장소에 뭐가 들어 있는지" 만 봅니다. 코드를 보고 답을 알 수
없습니다. 그 전까지 무슨 일이 있었는지를 봐야 합니다.
6번에서 다시 나옵니다 - 처음 온 사람의 저장소는 비어 있습니다.

이게 전부입니다. Day 08 비동기처럼 await 도 필요 없습니다. 바로 돌아옵니다.

점 표기법도 됩니다. 되지만 쓰지 마세요.

  localStorage.theme = "dark"          // 동작은 한다
  localStorage.length                  // 2? 1? - length 가 키 이름인지 개수인지 섞인다

Day 11 에서 form[name] 이 form 의 메서드를 다 가린 것과 같은 함정입니다.
setItem / getItem 으로만 쓰면 이 문제가 아예 없습니다.


4. 문자열만 들어갑니다 - 제일 많이 당하는 곳

┌───────────┬───────────────────┬─────────────────────────────────┐
│ 넣은 값   │ 꺼낸 값           │ 타입                            │
├───────────┼───────────────────┼─────────────────────────────────┤
│ 1         │ "1"               │ string                          │
│ true      │ "true"            │ string                          │
│ null      │ "null"            │ string                          │
│ undefined │ "undefined"       │ string                          │
│ [1,2,3]   │ "1,2,3"           │ string  <- 배열이 깨진다        │
│ {a:1}     │ "[object Object]" │ string  <- 객체는 완전히 깨진다 │
└───────────┴───────────────────┴─────────────────────────────────┘

숫자를 넣어도 문자열로 돌아옵니다. 그래서 이런 일이 생깁니다.

  localStorage.setItem("count", 5)
  const n = localStorage.getItem("count")
  n + 1        // "51"      <- 더하기가 아니라 붙이기
  +n + 1       // 6         <- 숫자로 바꿔서 더해야 한다
  Number(n)    // 5

배열과 객체는 더 심합니다. 그냥 넣으면 못 쓰게 됩니다.

  localStorage.setItem("list", [1, 2, 3])
  localStorage.getItem("list")         // "1,2,3"   - 배열이 아니다

  localStorage.setItem("user", { name: "노벨" })
  localStorage.getItem("user")         // "[object Object]"  - 내용이 사라졌다

왜냐면 setItem 이 값을 문자열로 바꿔서 넣는데,
객체를 문자열로 바꾸면 "[object Object]" 가 되기 때문입니다.


5. 그래서 JSON 을 거칩니다

  JSON.stringify(값)   값  -> 문자열   (넣을 때)
  JSON.parse(문자열)   문자열 -> 값    (꺼낼 때)

  // 넣기
  localStorage.setItem("list", JSON.stringify([1, 2, 3]))

  // 꺼내기
  JSON.parse(localStorage.getItem("list"))     // [1, 2, 3]  진짜 배열

이 두 줄이 localStorage 코드의 90% 입니다.
넣을 때 stringify, 꺼낼 때 parse. 한 쪽만 하면 안 됩니다.

JSON 으로 못 담는 것들이 있습니다.

  함수          사라진다
  undefined     사라진다 (객체의 그 키가 아예 없어진다)
  Date          문자열로 바뀐다 (parse 해도 Date 로 안 돌아온다)
  NaN, Infinity null 이 된다

Date 는 특히 조용히 당합니다.

  const d = new Date()
  const back = JSON.parse(JSON.stringify({ at: d }))
  back.at                  // "2026-11-09T05:00:00.000Z"  <- 문자열
  back.at.getFullYear()    // TypeError

날짜는 문자열("2026-11-09")이나 숫자(Date.now())로 저장하세요.
Day 11 에서 날짜를 YYYY-MM-DD 문자열로 비교한 게 여기서도 맞습니다.


6. 없으면 null 입니다 - 첫 방문자 문제

처음 온 사람의 localStorage 는 비어 있습니다.

  const list = JSON.parse(localStorage.getItem("list"))
  list.forEach(...)        // TypeError: list is null

  JSON.parse(null)         // null      (에러는 안 난다. null 이 그냥 나온다)

그래서 꺼낼 때 항상 기본값을 끼워야 합니다.

  const raw = localStorage.getItem("list")
  const list = raw ? JSON.parse(raw) : []

  // 또는
  const list = JSON.parse(localStorage.getItem("list") ?? "[]")

?? 는 왼쪽이 null 이나 undefined 일 때만 오른쪽을 씁니다.
|| 와 다릅니다. || 는 0 과 "" 도 넘깁니다.

  localStorage.getItem("count") ?? "0"     // 저장값이 "0" 이면 "0"
  localStorage.getItem("count") || "0"     // 저장값이 "0" 이어도 "0" (우연히 같다)
  // 하지만 count 가 "" 이면 ?? 는 "", || 는 "0" 으로 갈린다

localStorage 는 null 만 돌려주므로 ?? 가 정확합니다.


7. JSON.parse 는 터집니다 - try / catch

저장된 값이 JSON 이 아닐 수 있습니다.

  · 예전 버전의 내 코드가 다른 모양으로 저장했다
  · 사용자가 개발자도구로 손댔다
  · 저장 중에 탭이 죽어서 반쪽만 들어갔다

  JSON.parse("{abc")      // SyntaxError - 여기서 코드가 멈춘다

Day 11 쿠폰에서 fetch 를 try / catch 로 감싼 것과 같은 이유입니다.
읽는 쪽을 함수 하나로 만들고 그 안에서 막는 게 제일 깔끔합니다.

  function load(key, 기본값) {
    try {
      const raw = localStorage.getItem(key)
      return raw === null ? 기본값 : JSON.parse(raw)
    } catch {
      return 기본값          // 깨진 값은 버리고 기본값으로 시작한다
    }
  }

  function save(key, 값) {
    localStorage.setItem(key, JSON.stringify(값))
  }

이 두 함수를 만들어두면 나머지 코드에서 localStorage 를 직접 안 만집니다.
Day 11 에서 rules(판단) 와 say(화면) 를 나눈 것과 같은 모양입니다.
저장소를 만지는 곳이 한 군데면 나중에 sessionStorage 로 바꿀 때 두 줄만 고칩니다.


8. 키 이름은 겹칩니다

같은 주소(origin)의 모든 페이지가 저장소 하나를 같이 씁니다.
09-canvas 에서 "data" 로 저장하고 12-localStorage 에서도 "data" 로 저장하면
localhost:8777 안에서 서로를 덮어씁니다.

  나쁨    "data"  "list"  "user"  "temp"
  좋음    "study12:items"  "study12:fav"  "study12:read"

용도:이름 꼴로 접두어를 붙이세요. 지울 때도 편합니다.

  // 내 것만 골라 지우기 - clear() 는 남의 것까지 다 지운다
  Object.keys(localStorage)
    .filter(k => k.startsWith("study12:"))
    .forEach(k => localStorage.removeItem(k))

clear() 는 그 사이트 전체를 비웁니다. 같은 localhost 에서 돌리는
다른 과제의 저장값까지 날아갑니다. 거의 항상 removeItem 이 맞습니다.


9. 언제 저장할까

두 가지뿐입니다.

  바뀔 때마다 저장     - 체크 하나 누를 때마다 save()
  모아서 저장          - 작업이 끝날 때 한 번 save()

localStorage 는 동기(synchronous)입니다. 저장이 끝날 때까지 다른 게 멈춥니다.
작은 값이면 아무 문제 없습니다. 바뀔 때마다 저장하세요. 제일 안전합니다.

큰 값을 자주 저장하면 입력이 버벅입니다. 그때만 모아서 저장합니다.
(textarea 를 칠 때마다 수백 KB 를 저장하는 경우 - 그런 건 Day 08 의
 디바운스를 씌워서 "입력이 멈추고 500ms 뒤에" 한 번만 저장합니다)

주의: 저장하는 코드와 화면을 그리는 코드를 섞지 마세요.

  나쁨    버튼 클릭 -> 화면 고치고 -> 저장하고 -> 또 화면 고치고
  좋음    버튼 클릭 -> 데이터 고치고 -> 저장하고 -> 화면을 데이터로 다시 그린다

데이터 하나를 진짜로 삼고, 화면은 그걸 보고 그립니다.
그러면 "화면은 켜졌는데 저장이 안 된" 상태가 생기지 않습니다.


10. 용량은 약 5MB 입니다

넘으면 setItem 이 예외를 던집니다.

  QuotaExceededError: Failed to execute 'setItem' on 'Storage'

이미지를 base64 로 넣으면 금방 찹니다. 사진 한 장이 수백 KB 입니다.
localStorage 에는 "어떤 걸 골랐는지"만 넣고, 이미지 자체는 파일로 두세요.

진짜 넉넉하게 써야 하면 IndexedDB 가 있지만 대회 범위가 아닙니다.
저장은 try / catch 로 감싸두면 꽉 찼을 때도 페이지가 죽지 않습니다.


11. file:// 과 localhost 는 다른 저장소입니다

┌───────────────────────────┬────────────────────────────────────────────┐
│ 주소                      │ 저장소                                     │
├───────────────────────────┼────────────────────────────────────────────┤
│ file:///C:/.../index.html │ 별도 (브라우저마다 다르게 취급)            │
│ http://localhost:8777     │ localhost:8777 전용                        │
│ http://localhost:5500     │ localhost:5500 전용 (포트가 다르면 남이다) │
│ http://127.0.0.1:8777     │ 또 다른 저장소 (localhost 와 다르다)       │
└───────────────────────────┴────────────────────────────────────────────┘

Day 11 에서 fetch 때문에 서버를 띄웠습니다. 저장소도 같은 이유로 갈립니다.
file:// 로 열어서 저장해놓고 localhost 로 열면 아무것도 없습니다.
놀라지 말고 주소를 확인하세요.

시크릿 창도 따로입니다. 창을 닫으면 다 날아갑니다.
브라우저 설정에서 쿠키/사이트 데이터를 막아놓으면 setItem 자체가 터집니다.
그래서 읽기도 쓰기도 try / catch 를 씌우는 게 안전합니다.


12. 다른 탭에서 바뀌면 - storage 이벤트

같은 사이트를 두 탭에 열어두고 한쪽에서 저장하면,
다른 쪽에 storage 이벤트가 날아옵니다.

  window.addEventListener("storage", e => {
    e.key       // 바뀐 키
    e.oldValue  // 전     (문자열 또는 null)
    e.newValue  // 후     (문자열 또는 null, 지워졌으면 null)
    e.url       // 바꾼 페이지 주소
  })

중요한 함정 두 개입니다.

  · 저장한 그 탭에서는 안 울립니다. 다른 탭에서만 울립니다
  · removeItem 과 clear() 도 울립니다 (clear 면 e.key 가 null)

그래서 핸들러는 e.newValue 를 믿지 말고 다시 읽어서 그리는 게 안전합니다.


13. 자주 하는 실수

  stringify 를 빼먹음
    setItem(key, 배열)          -> "1,2,3" 으로 뭉개진다

  parse 를 빼먹음
    getItem(key).forEach(...)   -> 문자열에는 forEach 가 없다

  null 처리를 안 함
    처음 온 사람에게서만 터진다. 내 브라우저에는 이미 값이 있어서 안 보인다
    -> 개발자도구 Application 탭에서 지우고 다시 열어보세요

  숫자를 문자열로 비교
    getItem("count") > 9        // "10" > 9 는 true (여기선 우연히 맞다)
    getItem("count") > "9"      // "10" > "9" 는 false  <- 글자 순서로 비교했다

  clear() 를 씀
    남의 과제 저장값까지 날아간다

  저장은 했는데 화면을 안 그림 (또는 반대)
    데이터 -> 저장 -> 화면 순서를 고정하세요

  객체를 꺼내서 고치고 저장을 안 함
    const u = load("user", {})
    u.name = "노벨"             // 이건 메모리에 있는 사본이다
    // save("user", u) 를 안 하면 새로고침에 사라진다


14. sessionStorage 는 언제

  "이 탭에서 작업하는 동안만" 필요한 것

  · 작성 중인 글 임시 저장 (다른 탭에서 쓰는 글과 섞이면 안 된다)
  · 여러 단계 폼의 현재 단계
  · 방금 어디서 왔는지

쓰는 법은 똑같습니다. localStorage 를 sessionStorage 로 바꾸면 됩니다.
7번의 load / save 를 만들어뒀으면 그 안의 한 단어만 고치면 끝입니다.


15. 대회에서 나오는 모양

A모듈 문제은행 B9 번이 이렇습니다.

  "data.json 을 사용하여 목록을 렌더링하고 각 아이템마다 즐겨찾기 버튼을
   클릭해서 토글할 수 있도록 합니다.
   즐겨찾기 상태는 로컬스토리지에 저장하여 새로고침 해도 유지되어야 합니다.
   저장된 즐겨찾기 상태를 불러와서 렌더 시 버튼 상태에 반영해야 합니다."

딱 이 Day 가 전부입니다. 뼈대는 늘 같습니다.

  1) json 을 fetch 로 읽는다              (Day 08)
  2) 저장소에서 "사용자가 한 것" 을 읽는다  (Day 12)
  3) 둘을 합쳐서 화면을 그린다              (Day 06)
  4) 클릭하면 2) 를 고치고 저장하고 다시 그린다

json 은 원본입니다. 고치지 않습니다.
저장소에는 "원본에 대해 내가 한 일"만 넣습니다.

  나쁨    항목 20개를 전부 localStorage 에 복사해서 넣는다
          -> 원본 json 이 바뀌면 영원히 옛 데이터를 보게 된다
  좋음    즐겨찾기한 id 목록만 넣는다
          -> ["b3", "b7"]  이게 끝이다

이 구분이 이 Day 의 핵심입니다.
